# Order Management Platform

A Spring Boot microservices project built with Java 21, Maven, PostgreSQL, Flyway, and Docker Compose. The `auth-service` provides user registration, login, and JWT-based authentication.
---

## Prerequisite

Make sure you have the following installed:

- **Java 21** — required to run the application.
- **Maven** — required to build the application.
- **Docker Desktop or Docker Engine**.
- **IntelliJ IDEA** — recommended IDE for running and developing the services.
- **Git** — for cloning and managing the repository.

Verify your installations:

    java -version
    mvn -version
    docker --version
    docker compose version

## 1. Configure Environment Variables

The project uses environment variables to configure database connections and avoid hardcoding credentials.

From the repository root, create your local .env file using the example template:

    cp .env.example .env

Open .env and configure the values for your local environment.

For example:

    DB_HOST=localhost
    DB_PORT=5432
    DB_NAME=authdb
    DB_USER=order_platform_user
    DB_PASSWORD=your_local_password

    JWT_SECRET=replace_with_a_random_secret_at_least_32_bytes_long
    JWT_EXPIRATION_MINUTES=60

---

## 2. Start PostgreSQL with Docker Compose

From the repository root, run:

    docker compose up -d

This starts the infrastructure defined in docker-compose.yml in the background.

Docker Compose automatically reads the root .env file for variable substitution and configuration.

Check the running containers:

    docker compose ps

## 3. Configure Environment Variables in IntelliJ IDEA

Docker Compose reads .env automatically, but Spring Boot does not automatically load an arbitrary .env file when you run the application directly from IntelliJ IDEA.

To pass the variables to auth-service:

1. Open IntelliJ IDEA and open the auth-service run configuration.
2. Go to **Run → Edit Configurations**.
3. Select the run configuration for the Spring Boot application.
4. Click **Modify options**.
5. Select **Environment variables**.
6. Add the environment variables defined in .env file.
7. **Apply** the changes and click **OK**.

Ensure Docker Compose is running and the PostgreSQL database is ready.

Start auth-service using the Start button in IntelliJ IDEA..

## 5. Authentication API

### Register

`POST /api/auth/register`

Creates a user and returns **201 Created** with the public user representation. New registrations are assigned the `USER` role by the service; clients cannot choose their own role.

Example request:

```json
{
  "email": "user@example.com",
  "password": "a-strong-password"
}
```

Example response shape:

```json
{
  "id": "user-uuid",
  "email": "user@example.com",
  "role": "USER"
}
```

The response is illustrative; the `id` value should be a UUID generated by the application.

- Email must be valid.
- Password must be 8–72 characters.
- A duplicate email returns **409 Conflict**.
- Invalid request data returns **400 Bad Request** with field-level validation messages.

### Login

`POST /api/auth/login`

Authenticates an existing user and returns **200 OK** with a JWT response.

Example request:

```json
{
  "email": "user@example.com",
  "password": "a-strong-password"
}
```

Response shape:

```json
{
  "token": "<jwt>",
  "tokenType": "Bearer",
  "expiresInSeconds": 3600
}
```

The token is a signed JWT containing the subject, role, issued-at (`iat`), and expiration (`exp`) claims. A failed login returns **401 Unauthorized** with a generic message that does not disclose whether the email or password was incorrect.

### Get the current user

`GET /api/auth/me`

Requires a valid JWT in the `Authorization` header:

```http
Authorization: Bearer <jwt>
```

Returns the current user's public details, such as ID, email, and role.

### Health check

`GET http://localhost:8081/actuator/health`

Check the service health with:

```bash
curl http://localhost:8081/actuator/health
```

Expected response:

```json
{"status":"UP"}
```

The health endpoint, registration, and login are permitted without a JWT. Other endpoints require a valid JWT. Authentication errors should return JSON rather than an HTML login page.

## 6. Security Notes

- Use a strong, random `JWT_SECRET` of at least 32 bytes. It has no default and must not be committed.
- `JWT_EXPIRATION_MINUTES` defaults to 60 minutes.
- Passwords are hashed with BCrypt; never log or return raw passwords or password hashes.
- Keep `.env` out of Git and commit only `.env.example` with safe placeholder values.

## 7. Tests

Run the service tests from the `auth-service` directory:

first you need to JWT_SECRET to enviroment variable before you run the test command.

for windows open cmd/powershel and run

```bash
$env:JWT_SECRET="replace_with_a_random_secret_at_least_32_bytes_long"
```
verify it

```bash
$env:JWT_SECRET
```

On macOS

```bash
export JWT_SECRET="THE_VALUE"
```
verify it

```bash
echo "$JWT_SECRET"
```

Run the test using this command

```bash
mvn test
```

## 8. Stop the Application

Stop auth-service using the Stop button in IntelliJ IDEA.

To stop the Docker Compose services without deleting the database data, run this from the repository root:

    docker compose down -v

PostgreSQL initialization script only run on a fresh volume.
